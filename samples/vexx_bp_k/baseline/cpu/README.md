# vexx_bp_k CPU/OpenMP baseline (standalone)

Self-contained Fortran baseline for Quantum ESPRESSO's band-parallel exact-
exchange kernel `exx_bp::vexx_bp_k` (CPU, OpenMP) — compiles and runs from
this directory alone, no QE build required.

## contents

| file | role |
|---|---|
| `vexx_bp_k_baseline_cpu_omp.f90` | single TU: the OMP-preserving merged `vexx_bp_k` closure (byte-faithful, from QE develop/qe-omp, `!$omp`/`!$acc` intact) + the FFTW3 `fwfft_y`/`invfft_y` shim (QE conventions, cached threaded `FFTW_MEASURE` plans) + QE utility stubs (no-op clocks, loud `errore`).  Standalone pieces archived in `f2dace-qe-source/out_regex_omp/` |
| `verify_vexx.f90` | driver: loads a dump slot into the TU's module state, calls `vexx_bp_k`, verifies vs the QE ground truth, times reps |
| `build.sh` | build (auto-generates abort/no-op stubs for unreachable externals) |
| `run_verify.sh` | correctness gate: all slots x {full, nc}, machine-precision bound 1e-11 rel |
| `bench_full.sh` | performance: FULL mode, `WARMUP`/`REPS` env knobs (defaults 2/10) |
| `../../data/` | SHARED deck (all lanes: cpu/gpu/sdfg): BaTiO3_nat005_hse (PAW+US, HSE06, 24 bands, 40^3 EXX grid) boundary dumps, flat layout `vexx_{0..3,static,it1,it2}_<variable>.{bin,txt}` -- 4 slots = k-points {3,6} x exx iterations {1,2}, one self-consistent 32-thread pw.x trajectory + static tables + `MANIFEST.md5` + `PROVENANCE.txt`.  Populate with `../../download_data.sh` |

## requirements

MPI Fortran wrapper (`mpif90`; binary runs as an MPI *singleton* — no mpirun),
FFTW3 (+ `libfftw3_omp`), LAPACK/BLAS.  Override with `FC= FFLAGS= FFTW_INC=
LIBS=` env vars on `build.sh`.

## use

    ../../download_data.sh             # once: fetch/verify the shared deck into ../../data
    ./build.sh
    ./run_verify.sh                    # all 4 slots x full+nc -> ALL ... PASSED
    ./bench_full.sh                    # WARMUP=2 REPS=10, slot 0-3 @ 32 threads
    WARMUP=2 REPS=10 THREADS="1 8 32" SLOTS="0" ./bench_full.sh

Driver directly: `./verify_vexx <dumpdir> <slot 0-3> [full|nc] [reps] [warmup]`
(reps=0 -> verification only).  Always run under `ulimit -s unlimited` with
`OMP_STACKSIZE>=512M` (the scripts set both; without them the -O3 build
segfaults in the kernel's stack temporaries).

## semantics

* `full` = US+PAW operator (okvan+okpaw as in the run); ground truth
  `vexx_dump_<slot>_big_result_full.bin` = post-call hpsi from pw.x.
* `nc` = same inputs with augmentation gates off (norm-conserving Fock core);
  ground truth from the instrumented run's probe call.
* The first driver call verifies (bound: max rel err <= 1e-11 vs the exact
  pw.x hpsi; observed ~1e-16..1e-15) and doubles as warmup #1 (creates FFT
  plans + the coulomb_fac cache, which QE also reuses across SCF iterations —
  so timed reps measure the production steady state).
* Known scope: negrp == 1 (single band group), npol == 1.  The `aug` driver
  mode (qgm/vkb cross-probes) needs the older in-kernel dump schema, not
  included here.

Provenance/tooling (not needed to run): TU generated by
`f2dace-qe-source/run_regex_omp_vexx_bp_k.py`; dumps by the boundary-dump
instrumentation in `qe-omp/q-e/PW/src/exx_bp.f90` (`QE_DUMP_DIR`,
`QE_DUMP_EXIT`); dumped at OMP_NUM_THREADS=32 — thread count of the dumping
run and of this harness are decoupled (shared-memory inputs/outputs are
thread-count-invariant up to fp rounding, covered by the tolerance).
